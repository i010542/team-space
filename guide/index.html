共创入门

第一次参与 Skill 共创

每位协作者在自己的分支工作，在 GitHub 通过 PR 提交评审，审核通过后再合并。

分支 · Branch
为本次改动开的独立工作线。
提交 · Commit
记录一组改动和改动原因。
合并请求 · PR
让队友审阅改动，申请合入目标分支。

使用 GitHub Desktop

准备好仓库权限后，按下面的步骤完成一次协作。

  1. 01

    创建分支

    用有权限的账号登录 GitHub Desktop。首次使用，打开 File → Clone repository，选择团队仓库并克隆。通过 Current Branch 切到默认分支，拉取最新版本，再点 New Branch 新建自己的分支。

    分支名可用「成员名/任务名」，复制后换成自己的名字和任务。

    zhangsan/fva-shot-guide
    命令行做法（可选）
    git switch main
git pull --ff-only
git switch -c zhangsan/fva-shot-guide
  2. 02

    提交改动

    在本地编辑器修改文件。回到 GitHub Desktop 的 Changes 检查差异，填写 Summary 并提交。首次用 Publish branch 发布分支，后续用 Push origin 推送。

    命令行做法（可选）
    git status
git diff
git add SKILL.md
git commit -m "Clarify shot guidance"
git push -u origin zhangsan/fva-shot-guide
  3. 03

    发起 PR

    推送后打开 Preview Pull Request，再点 Create Pull Request。在 GitHub 网页核对来源分支和目标分支，写明改动和验证方式，并邀请队友评审。

  4. 04

    验证与修订

    按项目说明运行相关检查，并用代表性输入验证 Skill 行为。把通过、失败或未验证的项目写入 PR。根据评审意见在同一个分支继续提交和推送。

  5. 05

    审核后合并

    等评审意见和所需检查都处理完成，由有权限的协作者按仓库规则合并。合并后切回默认分支并拉取最新版本。

合并前检查

  • PR 说明改动目的、适用范围和验证结果。
  • 变更在自己的分支，目标分支选择正确。
  • 差异中没有密钥、私有素材或无关文件。
  • 评审意见与必要检查都已处理。
