# 团队共创空间 · Windows 客户端

面向在本地使用 AI 工具修改 Skill 的团队。自己的修改、团队协作和资料入口集中在工作台。GitHub 保存文件、个人分支和审核记录。当前接入 `i010542/fva`；查看或提交仍需要对应 GitHub 仓库权限。

## 成员怎么用

1. 从 [客户端下载页](https://i010542.github.io/team-space/) 安装 0.4.6 或更新版本，打开桌面上的 **团队共创空间**。先登录 GitHub：它是团队存放文件和审核修改的地方，需要使用团队已开通权限的账号。
2. 选择你正在使用的 FVA 中的 **SKILL.md** 文件。客户端自动记住它所在的文件夹，检查整个 Skill 的改动，你的文件留在原处。
3. 照常用 WorkBuddy、Codex 等工具使用和修改这份 FVA，改完记得保存。
4. 回到客户端，点 **刷新改动**，查看这次的全部改动并写一句说明，再点 **发给团队审核**。
5. 在客户端查看审核进度。有反馈就继续修改原文件，再次发送。只有负责人审核并采纳后，修改才会进入团队正式版本。
6. 想使用团队新版时，点 **检查团队更新**。如果一个文件你和团队都改过，需要选好用哪一份；确认后点 **更新我的 FVA**，客户端会先备份再更新。更新完成前请暂停修改。

在工作台的“团队协作”中，可以通过大卡片查看团队文件、大家的修改版本、待审核的修改，或提出问题和建议；这些按钮先打开 github.io 的白话说明页，再由你点击进入 GitHub。资料搜索和日常协作仍在客户端里操作。

工作台上方的 **查看文档** 可直接打开本地资料目录。发送时自动包含全部已检测到的改动（新增、修改和删除），不再逐个勾选。若列表中有不能发送的文件，或超过一次 100 个文件的上限，整批暂停并提示原因；不会悄悄漏掉文件。原有目录排除和受保护文件规则仍然生效。

当前支持单个不超过 1 MB 的 UTF-8 文本文件；图片、视频、账号凭据等不能通过这里发送。客户端不会自动运行 Skill 或生成视频。

上次没发完时，可点 **继续发给团队**。如果上一轮审核已结束或无法继续，可选择 **保留文件，开始新一轮**。你的 FVA 文件和旧修改记录会保留，仍然使用原文件夹。

## 网页与客户端

本地客户端是统一工作入口：查看团队内容、查找资料、阅读使用帮助、选择原 FVA 的 SKILL.md、查看修改、发给团队审核、备份更新与恢复都从这里进入。需要 GitHub 授权、阅读仓库原文或人工审核时，再通过明确的外链打开浏览器。

github.io 提供客户端下载、升级、唤起，以及团队协作的白话说明和资料目录。实际文件和审核记录仍在 GitHub，日常修改与发送仍从客户端操作。首次参与的三个步骤可以点击，第三步先定位到改动列表，不会直接发送。

网页打开客户端只负责导航，不会自动选择文件夹、提交审核或应用更新。正在操作或填写说明时，网页请求会等待用户继续，保留当前内容。网页无法可靠判断本机是否安装或已经打开客户端，未弹出时请安装或升级后重试。

安装程序注册 `teamspace-app` 外部协议，固定允许 `teamspace-app://project/fva`、`teamspace-app://project/fva/docs` 与 `teamspace-app://project/fva/updates`。它与内部页面协议分开；链接不携带本地路径或账号凭据。仅运行解压的程序不能代替安装程序注册。

## 开发与打包

使用 Windows x64、Node.js 22 或更新版本：

```powershell
npm ci
./scripts/fetch-tools.ps1
npm test
npm start
npm run package
```

安装包位于 `release/`。内置 Git 和 GitHub CLI，使用官方发布文件并检查固定 SHA-256，不要求同事手工安装开发工具。后台版本记录保存于 Electron 用户数据目录；实际 Skill 留在用户选择的原目录。卸载程序保留工作数据。

## 边界

- 渲染界面仅加载打包的本地内容；启用沙箱、上下文隔离、内容安全策略，禁止远程导航和任意命令 IPC。
- Git/GitHub 命令以固定参数调用，不经过 shell。界面不接收 GitHub token。
- 新任务使用独立目录和个人分支；提交前核对仓库、分支、账号和预览状态，仅包含确认时列出的改动文件。
- 默认分支不由客户端直接提交或合并；更新失败或发生分叉时停止，不强制推送、清空文件或自动丢弃修改。
- 不配置静默自动更新。安装包暂未做商业代码签名；不应通过关闭系统安全功能来绕过安装限制。
- 第一版会阻止带 Git 内容转换属性的文件，以及 Windows 无法区分的大小写路径冲突。文件被拦截时，界面会说明原因。

第三方软件和对应源码见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。真实仓库写入与多台电脑登录的验证范围会在每次发布说明中列明。

## 绑定与更新

首次差异以绑定时的团队版本为对照，不推断已安装版本，已有修改不会当成已同步。安装目录从未包含的仓库文件不会被当作删除。

检查团队更新不会修改本机文件。确认应用时，先保存备份，合并能够自动处理的文本差异；同一处有改动时，必须明确选择保留本机或采用团队内容。对于没有可信安装版本记录的旧目录，不能推断修改来源，差异会保守地交给用户确认。

冲突选择保留本机时，该文件暂缓提交，避免将旧团队内容带回正式版本。可在原目录手动合并所需团队内容，再重新检查更新并确认保留本机，继续提交自己的修改。

有待发送的提交或仍在审核中的请求时，可以查看更新，完成本轮审核后再应用。应用更新会建立以目标团队版本为起点的新后台任务，避免把团队的更新误当作个人修改提交。旧后台任务继续保留。

更新和恢复时请暂停编辑。预览后内容发生变化会阻止更新；失败会尝试回滚，若中断则从工作台恢复。更新后的文件又被修改时，恢复会停止，不覆盖新修改。备份保存在客户端后台数据中，不上传 GitHub。

中断恢复使用本地记录，断网时也可操作。更新后已经产生新提交或审核时，不直接恢复旧任务，以免丢失提交状态；需要先与维护者处理这轮任务。

0.1 版用户升级后需选择正在使用的 FVA 中的 SKILL.md，旧工作目录不会删除。0.2 版的绑定继续保留。

切回工作台只提醒刷新，不会自动重新读取或清除说明；保存文件后请点击“刷新改动”。操作的界面更新出错时会结束忙碌提示，不会自动重试发送。
