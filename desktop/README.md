# 团队共创空间 · Windows 客户端

面向在本地使用 AI 工具修改 Skill 的团队。GitHub 保存文件、个人分支和审核记录，客户端提供中文操作界面。当前接入 `i010542/fva`；查看或提交仍需要对应 GitHub 仓库权限。

## 成员怎么用

1. 安装并打开 **团队共创空间**，选择 **登录 GitHub**，在系统浏览器中完成授权。不要将授权码发给别人。
2. 选择 **开始参与 FVA**。客户端准备独立工作文件夹和个人分支。
3. 选择 **打开工作文件夹**，让 WorkBuddy、Codex 或其他编辑工具在这个文件夹中修改 Skill。
4. 回到客户端，刷新改动，勾选需要提交的文件，查看差异并填写修改说明，选择 **提交审核**。
5. 查看审核状态。需要修订时继续修改同一工作文件夹并再次提交；正式版本由仓库维护者审核合并。

本地文件夹路径会在客户端展示。第一版仅提交单个不超过 1 MB 的 UTF-8 文本文件；二进制素材、凭据和受保护路径不通过这个入口提交。不会自动运行 Skill 脚本或生成视频。

如果上次发送未完成，可以选择 **继续上次提交**。若原审核已经结束，或旧快照无法继续，选择 **保留文件，另开任务**；旧工作文件夹和本地提交不会删除，需要的修改由成员从旧文件夹复制到新的工作文件夹。

## 开发与打包

使用 Windows x64、Node.js 22 或更新版本：

```powershell
npm ci
./scripts/fetch-tools.ps1
npm test
npm start
npm run package
```

安装包位于 `release/`。内置 Git 和 GitHub CLI，使用官方发布文件并检查固定 SHA-256，不要求同事手工安装开发工具。所有本地工作文件保存于 Electron 用户数据目录下，不写进安装目录，卸载程序保留工作数据。

## 边界

- 渲染界面仅加载打包的本地内容；启用沙箱、上下文隔离、内容安全策略，禁止远程导航和任意命令 IPC。
- Git/GitHub 命令以固定参数调用，不经过 shell。界面不接收 GitHub token。
- 新任务使用独立目录和个人分支；提交前核对仓库、分支、账号和预览状态，仅包含所选文件。
- 默认分支不由客户端直接提交或合并；更新失败或发生分叉时停止，不强制推送、清空文件或自动丢弃修改。
- 不配置静默自动更新。安装包暂未做商业代码签名；不应通过关闭系统安全功能来绕过安装限制。
- 第一版会阻止带 Git 内容转换属性的文件，以及 Windows 无法区分的大小写路径冲突。文件被拦截时，界面会说明原因。
